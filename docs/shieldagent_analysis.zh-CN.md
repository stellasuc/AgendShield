# SHIELDAGENT 技术分析与 AgentShield 边界

[English](shieldagent_analysis.md)

## 范围与来源

本文基于对本地 25 页论文 `ShieldAgent.pdf` 的完整审阅。论文题为 *SHIELDAGENT: Shielding Agents via Verifiable Safety Policy Reasoning*，发表于 ICLR 2025 Workshop on Foundation Models in the Wild。AgentShield 是独立工程扩展，不使用、不修改，也不声称复现 SHIELDAGENT 官方源代码。

## 威胁模型

SHIELDAGENT 保护的自主 Agent 可能受到内部配置或外部环境的对抗性操纵。论文区分 Agent-based 攻击（如被污染的指令、记忆、知识库或工具）与 Environment-based 攻击（如恶意网页内容）。受保护表面是一条动作轨迹：不安全行为可能跨越连续的 Agent/环境交互逐步出现，并造成访问控制失败、隐私泄露、经济损失、内容策略违规、幻觉、操作错误或长期伤害（第 1、2.1、4 节及附录 E）。

Guardrail 会接收当前观察、待执行动作以及此前交互历史。系统信任 Guardrail 能够检索和解释安全策略模型、收集证据、校验规则并将提议动作标记为安全或不安全。论文没有声称 Guardrail 能防止主机失陷、使策略提取具有法律权威性，或消除模型与检测器错误。

## 基于动作的安全策略模型（ASPM）

ASPM 是逻辑知识图 `G_ASPM = (P, R, pi_theta)`（第 3.1–3.2 节）：

- `P = {P_a, P_s}` 将谓词划分为动作谓词和状态谓词；
- `R = {R_a, R_p}` 将约束划分为动作规则和物理规则；
- `pi_theta` 是按动作相关规则电路组织的概率逻辑模型。

离线构建管线从法规、组织策略或用户约束中提取结构化策略；将其翻译为 LTL/LTLf 风格规则；迭代提高可验证性；裁剪冗余；按动作和依赖聚类规则；再根据标注或模拟数据学习软规则权重。论文在每个提取出的策略块中保留来源材料引用。

## 动作谓词与状态谓词

**动作谓词**表示将要执行的动作，例如删除、发布、发送或邀请。直接约束动作的规则必须至少包含一个动作谓词。**状态谓词**描述可观察的环境或系统条件，例如数据是否机密，或用户是否授权某项操作。每个谓词预期在某一时间步获得布尔值。

物理规则编码状态变量之间的关系，但不直接约束动作。它们充当领域知识，使推理在某个谓词被错误赋值时仍具有鲁棒性。附录 A.2 展示了动作规则（“机密且未授权 → 不得删除”）和物理分类规则。

## 策略表示

策略提取阶段生成自包含区块，包括术语定义、适用范围、策略描述和引用。规则提取阶段将规则表示为 `r = [P_r, T_r, phi_r, t_r]`，包含谓词、自然语言约束、LTL 表示和规则类型。附录 H 的 Prompt 强调原子化、可观察谓词与来源可追溯性。

Verifiability Refinement 用于纠正不准确逻辑表示、拆解模糊或复合规则，并尝试使谓词可观察。Redundancy Pruning 对语义相关谓词聚类，并在尽量保持含义的情况下合并冗余规则。论文允许在自动精炼后加入人工专家审查。

## 规则电路与概率推理

具有强关联或语义相似状态谓词的规则会被聚类。对于每个动作谓词，SHIELDAGENT 合并相关聚类以形成动作特定电路。推理时只检索与当前动作相关的电路，从而减少相对于遍历完整策略的工作量。

在电路内部，马尔可夫逻辑网络为谓词世界分配加权概率。SHIELDAGENT 比较“执行该动作的世界”与“不执行该动作的反事实世界”的概率。可配置阈值产生最终二元安全标签。软规则权重使用 Guardrail hinge loss 学习，因此不可靠或重要性不同的规则无需成为同权硬约束（第 3.2.4 节与附录 C.5）。

## Shielding Plan 与操作

系统检索当前动作的规则电路后，会从长期记忆中检索相似的成功校验工作流。这些示例用于生成分步 Shielding Plan；其中的操作会为尚未赋值的状态谓词收集真值。计划持续到所有相关谓词均已赋值，或满足提前终止条件。随后系统生成可执行模型检查代码，验证各条规则，执行概率电路推理，并返回安全标签、违反规则和解释（算法 1 与第 3.3 节）。

四类操作为：

- **Search**：从交互历史中检索并列举相关信息；
- **Binary-Check**：为查询分配二元标签；
- **Detect**：调用针对风险类别和模态的审核工具；
- **Formal Verify**：在规则表示上运行模型检查算法。

论文描述了多模态审核 API、针对 Search 与 Binary-Check 的专门微调模型，以及 Stormpy 等形式化验证工具。AgentShield 没有复现这些训练组件或概率电路。

## 动作级校验工作流

算法 1 可概括为：

```text
当前动作
  -> 提取动作谓词
  -> 检索动作相关规则电路
  -> 检索成功的 Shielding 工作流
  -> 规划 Search / Binary-Check / Detect / Formal Verify 操作
  -> 根据观察与历史为状态谓词赋值
  -> 形式化校验相关规则
  -> 概率电路推理
  -> 安全/不安全标签 + 违反规则 + 解释
```

在线实验将此决策作为逐步的事后校验反馈集成到 Web Agent，使其能够调整后续行为。AgentShield 则面向具有副作用的边界进行执行前检查，并使用显式干预/修复循环。

## 历史与记忆的使用

SHIELDAGENT **确实使用历史**。公式（1）向 Guardrail 提供此前交互历史 `H_<i`、当前观察和当前动作。Search 会显式查询 `H_<=i`。其混合记忆包括：

1. 短期交互历史，以 KV Cache 增量保存，并在当前动作序列验证后丢弃；
2. 成功 Shielding 工作流的长期记忆，作为可复用示例被检索并持续更新。

因此，“SHIELDAGENT 不使用历史”是不准确的。AgentShield 有意义的区别并非“是否使用历史”，而是显式、持久、类型化的合规状态与数据血缘模型会跨异构生命周期事件更新。

## AgentShield 借鉴的设计思想

AgentShield 在架构层面借鉴：

- 依据策略而不是只依赖模型记忆做决策；
- 原子谓词与结构化规则评估；
- 只检索与动作/事件相关的规则；
- 收集规则所需事实；
- 在稳定校验器接口后使用确定性或形式化验证；
- 显式输出违反规则与基于来源的解释；
- 可扩展的 Search、Binary-Check、Detect 和 Formal Verify 操作插槽。

本地实现为原创代码。运行时会基于真实 Broker 动作生成规则电路、原子谓词 TRUE/FALSE/UNKNOWN 赋值、确定性 LTL 风格验证和可审计的 Shielding Plan；`ShieldAgentStyleVerifier` 仍是可扩展接口。项目不声称等价于论文中的训练模型、ASPM 训练、马尔可夫逻辑网络或基准结果。

## 属于 SHIELDAGENT、AgentShield 不作声明的能力

以下属于论文能力，并非 AgentShield 的实现声明：

- 从长文档自动提取 LLM 策略与 LTL 规则；
- 迭代式模糊性引导规则精炼与语义冗余裁剪；
- 基于动作的概率电路与训练得到的软规则权重；
- 马尔可夫逻辑网络推理与相对安全概率阈值；
- 微调的 Search 与 Binary-Check Guardrail 模型；
- 多模态审核和基于 Stormpy 的形式化模型检查；
- 论文描述的长期学习工作流记忆；
- SHIELDAGENT-BENCH、其数据或论文报告的性能。

## AgentShield 的生命周期级扩展

两者的操作差异可表示为：

```text
SHIELDAGENT
当前动作
  -> 检索动作相关规则
  -> 基于相关状态/历史推理
  -> 校验当前动作
  -> 允许/阻断

AgentShield
运行时生命周期事件
  -> 更新持久合规状态
  -> 跟踪数据血缘与义务
  -> 识别受影响的法规/规则
  -> 执行事件驱动校验
  -> 允许 / 阻断 / 修复 / 要求审批
  -> 继续执行
```

AgentShield 将强制执行扩展到用户请求、计划、工具调用与结果、外部传输、记忆写入、日志、同意更新、审批和信任边界响应。数据以对象身份、分类、目的、转换、接收方和来源表示，因此聚合结果可以不再是个人数据，同时不会抹除原始来源的分类。变量到规则索引会在状态差异无法影响规则时跳过校验，而具有副作用或跨信任边界的事件始终被检查。修复会创建新事件和数据对象，记录来源，更新状态，并在发布前重新校验。

当前架构进一步把这套校验用于独立 Capability Broker 内的持久副作用事务，并将每次实际动作的 Shielding Plan 写入审计；但并未引入论文中的概率推理或训练组件。

这是对策略校验模式的独立工程扩展，不声称对所有历史感知 Guardrail 具有创新性，也不修改 SHIELDAGENT 官方代码。
