# 威胁模型

[English](threat_model.md)

## 安全目标

AgentShield 的目标是确保：通过参考 Broker 暴露的安全敏感副作用，在调用原始后端之前，已经完成能力注册检查、策略校验、持久化授权、必要时的限定范围人工审批，以及可审计记录。

它是 Brokered 能力的参考监控器，不是通用 Python 沙箱，也不是法律合规判断器。

## 受保护资产

- 工具结果和派生对象中的个人信息及敏感个人信息；
- 外部邮件、持久记忆和响应发布权限；
- 审批范围与同意/治理证据；
- 事务、副作用和策略决策完整性；
- 用于防止重复副作用的幂等状态；
- 载荷最小化的审计证据。

## 主体与边界

| 主体/组件 | 信任定位 |
| --- | --- |
| Agent 计划、参数、检索内容与工具内容 | 不可信 |
| `BrokerClient` 调用方 | 只允许提出请求，不可信任其授权 |
| 能力注册表与风险元数据 | 可信部署输入 |
| Broker、策略引擎、Adapter、Gateway | 可信计算基 |
| 人工审批者 | 仅在记录的精确范围内可信 |
| SQLite 数据库 | 敏感、可信、需要访问控制的存储 |
| Mock 后端 | Broker 持有的副作用；其结果仍是不可信数据 |
| 法规包/检测器 | 有意不完整且可能出错的精选输入 |

## 范围内威胁

- Agent 请求未知或权限过大的能力；
- 只需聚合数据时，却向外部传输原始个人信息；
- 将敏感内容写入持久记忆；
- 个人信息通过最终响应泄露；
- 没有授权事务，或以错误能力尝试副作用；
- 修复未经新一轮校验就执行；
- 过期或无关审批被用于其他对象、目的、接收方或操作；
- 获批提案在执行前被修改；
- 重试或 Broker 重启导致已提交副作用重复执行；
- 崩溃后遗留结果未知的执行中副作用；
- 审计或 CLI 展示泄露原始载荷；
- 工具结果中的恶意指令试图影响策略层。

## 控制与证据

| 威胁 | 控制 | 回归证据 |
| --- | --- | --- |
| 未知操作 | 固定能力注册表 | 创建事务前拒绝 |
| 直接调用网关 | 持久状态与能力匹配检查 | 未授权网关测试 |
| GDPR 过量传输 | 血缘感知的最小化修复 | 原始 PII 计数 0；聚合计数 1 |
| 不安全记忆 | 副作用前策略检查 | 阻断后及重试后存储计数均为 0 |
| 响应泄露 | 发布前脱敏 | 发布值已脱敏 |
| 修复绕过 | 阻断父事务与重新校验子事务 | 父子事务断言 |
| 审批混淆 | 范围严格相等 | 错误范围审批被拒绝 |
| 审批变成绕过 | `WAITING_APPROVAL -> CHECKING` | 审批审计先于授权 |
| 重复副作用 | 持久化唯一 `effect_id` | 重启后重放，计数保持 1 |
| 崩溃结果未知 | 启动恢复状态 | `EXECUTING -> REQUIRE_HUMAN_REVIEW` |
| 展示面泄露 | 载荷指纹 | 审计与 CLI 中不存在原始测试数据 |
| 进程内原始句柄 | 独立 Broker 与窄客户端 | PID 不同且接口表面检查通过 |

## 信任假设

- Agent 对声称受保护的能力使用 BrokerClient；
- Broker 主机、代码、注册表、数据库权限与策略配置可信；
- Agent 没有其他原始邮件、数据库、Shell、网络、回调、插件或记忆权限；
- 演示环境中，本机回环端点只可被预期主体访问；
- 人工审批和 Broker 提供的治理事实真实；
- SQLite 可用，且文件系统语义正确；
- 顺序化 Broker 处理足以满足该本地参考部署。

## 范围外事项

- OS、Python 解释器、Broker 进程、策略包或数据库失陷；
- Agent 在 Broker 之外打开任意网络、Socket、子进程、文件等通道；
- Broker 端点的认证、授权令牌、TLS/mTLS、限流与多租户隔离；
- 静态加密、秘密管理、签名元数据、防篡改审计与远程证明；
- 与真实外部服务实现原子的精确一次协调；
- 分布式 Broker、副本、跨区域副作用或并行工作流提交；
- 可信后端实现内部隐藏的嵌套副作用；
- 完整防御提示注入；
- 检测器零误差、完整法条覆盖或法律结论。

## 失败策略

未知能力在持久化前失败。未知的高风险策略事实会阻断或要求审批。网关从持久状态校验授权。核心运行时的审计失败默认关闭执行。重启时发现的执行中事务会升级为人工审查，而不是自动重试。

Broker 服务有意保持最小化，演示封装器会终止子进程；SQLite 提交使已完成状态保持持久。生产实现需要优雅关闭、认证 IPC、存储加密、服务商级幂等键、并发租约/栅栏和操作恢复流程。

AgentShield 提供的是可辅助合规项目的技术控制。审批记录、检测器标签和选定策略规则是软件使用的证据，不是法律意见、同意证明或 GDPR/PIPL 合规保证。
